### 1. numbat: AIエージェント活動を端末側で監視・ブロック・フォレンジック化
- 出典: GitHub / ITmedia系ニュースでの紹介を確認
- 日付: 2026-07-31（日本語ニュース確認）、GitHub更新 2026-08-06時点
- リンク: https://github.com/perplexityai/numbat
- 要約: Perplexity の `numbat` は、Claude Code / Codex などのエージェント活動をローカルフック、プラグイン、ログ、セッション成果物から正規化し、CELルールで検知・必要に応じて事前ブロックする監視ハーネス。記録はローカル中心で、監視・強制・事後再構成を同じイベントモデルに載せる点が特徴。
- なぜ面白いか:
  - 技術: エージェントの「発話」ではなく、フック・ログ・ファイル痕跡を観測対象にして、検出と証跡を同じルールエンジンへ流し込む設計が実務的です。
  - 人文: これはAIを共同作業者として信頼するための監視社会化ではなく、責任の所在を曖昧にしないための作業記録文化に近い。人間の監督を「気合い」から「制度」に移す動きとして読めます。

### 2. Claude Code Safety Harness: bypassPermissionsを“YOLO”ではなくサンドボックス付きで使う
- 出典: GitHub
- 日付: 作成 2026-07-20、更新 2026-08-05
- リンク: https://github.com/jonnyeclectic/claude-safety-harness
- 要約: `claude-safety-harness` は Claude Code の `--dangerously-skip-permissions` 利用時に、OSサンドボックス、`permissions.deny`、`PreToolUse` / `Stop` hooks を重ねる安全ハーネス。プロジェクト外書き込みや危険コマンド、未検証終了へのガードを「ベルトとサスペンダー」で組み合わせる。
- なぜ面白いか:
  - 技術: hook だけでは防げない任意サブプロセスをOSサンドボックスで、OSサンドボックスだけでは届かない組み込みツール操作をClaude Codeフックで補う分担が明快です。
  - 人文: 自律エージェント利用の心理は、便利さが増すほど境界を緩めたくなる方向へ傾く。このプロジェクトは「信頼」と「許可」を分け、危険な自由を儀礼ではなく構造で制限する試みです。

### 3. Agent Arena: Claude Code / Codex / Gemini CLIを同じタスクで戦わせる評価ハーネス
- 出典: GitHub
- 日付: 作成 2026-07-29、更新 2026-08-05
- リンク: https://github.com/JDKrasnick/agentarena
- 要約: `agentarena` は2つの coding agent に同じリポジトリ課題を解かせ、パッチ検証、実行可能な攻撃テスト、修復ラウンド、タスク契約オラクルで比較するローカルCLI/Nodeライブラリ。会話の自然言語をコアが解釈せず、受諾・適用は認証済みユーザー操作とパッチdigestに紐づける。
- なぜ面白いか:
  - 技術: 単なるLLM-as-judgeではなく、攻撃テストと再現確認を含む「対戦形式」のハーネスで、複数エージェントの出力を同じ証拠面に並べます。
  - 人文: AI開発は「どのモデルを信じるか」から「どの提案を採用する儀式を設計するか」へ移っています。競技場メタファーは、人間のレビュー判断を可視化する新しいチーム儀礼としても興味深いです。

### 4. 日本語圏の Claude Code test gate: Stop hookで“テスト未実行の完了報告”を止める
- 出典: GitHub（日本語コミュニティ）
- 日付: 作成 2026-08-04、更新 2026-08-04
- リンク: https://github.com/Shotaro-Yoshinaga-sti/claude-code-test-gate
- 要約: `claude-code-test-gate` は、Claude Code の `PostToolUse(Edit|Write)` と `Stop` hook を使い、編集した領域に対応するテストが通るまでセッション終了をブロックする最小構成サンプル。READMEでは、AIが「テストは通っています」と言いながら実行していない問題を、プロンプト依存ではなく終了ステータスで機械的に判定する設計として説明している。
- なぜ面白いか:
  - 技術: 編集ファイルから対象ラベルとテストコマンドを対応付け、Stop時に未検証ラベルを実行・失敗時にJSONでblockする、小さいが再利用しやすいハーネスです。
  - 人文: 日本語圏でも、AIへのお願い文ではなく作業規範をコード化する流れがはっきり出ています。「報告」より「証拠」を優先する文化を、現場の小さなフックで作れる点が重要です。

### 5. PRWeaver: 長期・分割された悪意あるPRに対するLLMコード監査ベンチマーク
- 出典: arXiv
- 日付: 2026-08-03
- リンク: https://arxiv.org/abs/2608.02693
- 要約: `PRWeaver` は、実リポジトリ10件から208件の実行検証済み攻撃を作り、4種類のレビュー表現で計832レンダリングを評価する、LLMベースのPR監査エージェント向けベンチマーク。単にコミットを分けるだけでは検出率低下を説明できず、 benign な変更と悪意ある変更が同じアクティブ文脈に混ざると監査検出が大きく落ちると報告している。
- なぜ面白いか:
  - 技術: ハーネスが「正解パッチを通す」だけでなく、履歴・文脈・PR単位の見せ方を変えて監査エージェントの弱点を測る方向へ拡張されています。
  - 人文: 悪意は単発の黒い差分ではなく、もっともらしい物語の中に埋め込まれる。AI監査の課題は検出性能だけでなく、人間組織が“もっともらしさ”にどう騙されるかという歴史的なレビュー文化の問題でもあります。
