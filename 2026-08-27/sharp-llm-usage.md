## トップ5

### 1. LLMが書いたテストを信頼する方法 — テスト義務ゲート

- 出典: Qiita記事
- 日付: 2026-08-26
- リンク: https://qiita.com/Flip451/items/051aac37022af6823e51
- 要約: LLMに「実装とテスト」を同時に書かせたとき、greenなテストをそのまま信じるのではなく、テスト自体が仕様をどう保証するかを問う実践論。出力コードの全面レビュー、人間の直感、AI判定器、テスト通過のそれぞれの限界を整理し、「テストを信頼するためのゲート」を設計課題として扱っている。
- なぜ面白いか:
  - 技術: 生成コードの信頼性を、モデル性能ではなく「テスト集合の網羅性・仕様対応・検証ゲート」に分解して扱う点が実務的。
  - 人文: “AIが書いたものを誰が信じるのか”という責任の問題を、信頼の委譲ではなく制度設計として捉えている。これは職人の勘から監査可能な工程へ、ソフトウェア制作文化が移る兆しでもある。

### 2. AIエージェントとの協働を円滑にする「索引」ベースの情報設計

- 出典: Qiita記事
- 日付: 2026-08-25
- リンク: https://qiita.com/sh39/items/0904bc1e78e869e1f151
- 要約: AIエージェントとの協働で発生するコンテキスト肥大化を防ぐため、タスクリストや参照ドキュメントを「蓄積型」ではなく「索引型」にする提案。状態とリンクだけを軽く持ち、詳細文書をオンデマンドで読ませることで、トークンコストと注意の散漫さを抑える。
- なぜ面白いか:
  - 技術: コンテキストウィンドウを大きくするのではなく、情報アーキテクチャで必要な文脈だけを引けるようにする“コンテキスト・エンジニアリング”の実例。
  - 人文: 人間のチームでも優れたプロジェクト管理は「全部を覚える」ことではなく「どこを見ればよいか」を共有することだった。AI協働も同じく、記憶より索引、饒舌より参照性が価値になる。

### 3. AIによるレビュー精度を保つ方法

- 出典: Qiita記事
- 日付: 2026-08-22
- リンク: https://qiita.com/Tsutomu_eng/items/d40f674449298a5ee6ce
- 要約: Claude CodeなどのAIエージェントにPRレビューをさせると、同じdiffでも指摘内容がぶれるという問題を出発点に、独自CLI「Revi」の設計を紹介。直前の会話履歴によるバイアス、レビュー観点の揺れ、コンテキストの与え方などを、CIに組み込める安定したレビュー工程へ落とし込もうとしている。
- なぜ面白いか:
  - 技術: AIレビューを単発チャットではなく、入力差分・観点・実行環境を固定した再現性あるCLIワークフローとして扱う点が鋭い。
  - 人文: レビューとは単に欠陥を探す行為ではなく、チームが何を重視するかを可視化する儀式でもある。AIレビューの“ぶれ”を抑える試みは、チームの価値基準を機械に翻訳する試みでもある。

### 4. Anchoring Bias in LLM-as-a-Judge Systems: Prior Scores Compromise Evaluation Independence

- 出典: arXiv論文
- 日付: 2026-08-26
- リンク: https://arxiv.org/abs/2608.25869
- 要約: LLM-as-a-Judgeに過去スコアや改訂メタデータを含めるだけで、評価がその値に引き寄せられることを大規模実験で示した研究。評価器としてLLMを使う反復改善パイプラインでは、前回評価を文脈に入れること自体が独立性を壊す可能性がある。
- なぜ面白いか:
  - 技術: LLM評価を検証ゲートに使う際、評価プロンプトだけでなく「評価器に渡すメタデータ」がバイアス源になると明確に示している。
  - 人文: 人間の採点者が前評判や点数に引きずられるのと同じ構造が、機械評価にも現れている。AIを中立な審判と見なす物語に、かなり実務的な歯止めをかける研究である。

### 5. Agentic Loop / Plumbline / Babelに見る「検証証拠つきエージェント工程」の台頭

- 出典: GitHubリポジトリ群（Web調査）
- 日付: 2026-08-18〜2026-08-27に更新確認
- リンク: https://github.com/bartoszarendt/agenticloop / https://github.com/BytesFromToby/plumbline / https://github.com/gthgomez/Babel
- 要約: Agentic Loopはタスク契約、ロール境界、検証ルール、永続的プロジェクト記憶をMarkdown-firstで与えるオーバーレイ、Plumblineは仕様を真実の基準にして逸脱ログとテスト証拠を残すClaude Code向けスキル群、BabelはChat/Plan/Deepモードと可視化されたPrompt OSを持つローカル coding agent harness として説明されている。共通して「エージェントに任せる」より「工程・権限・証拠を構造化する」方向へ寄っている。
- なぜ面白いか:
  - 技術: プロンプトを改善するだけでなく、計画モード、権限境界、レビューゲート、逸脱ログ、テスト証拠をリポジトリ内の成果物として残す設計が共通している。
  - 人文: これは“AIに魔法のように作らせる”段階から、“未熟だが速い同僚をどうチーム工程に参加させるか”への転換に見える。信頼は人格ではなく、記録・境界・再検証から作られるという近代的な労働観が、AI開発にも流れ込んでいる。

## arXiv / 学術

- Repair or Resample? Rethinking Failure Debugging in LLM Multi-Agent Systems — arXiv:2608.25920（2026-08-26）。マルチエージェント失敗の修復が本当に因果的修復なのか、単なる再サンプリング運なのかを、実行軌跡の再生と介入アンカーで検証する研究。
- From Passive Response to Proactive Correction: Enhancing LLM Robustness Against Input Fact Perturbations — arXiv:2608.25894（2026-08-26）。ユーザー入力自体に誤前提がある場合、LLMがそれを検出・訂正してから答えるDEDUCEフレームワークを提案。
- Anchoring Bias in LLM-as-a-Judge Systems: Prior Scores Compromise Evaluation Independence — arXiv:2608.25869（2026-08-26）。トップ5の4件目として採用。
- Localize-Then-Decide Guarantees for LLM Judgments — arXiv:2608.25824（2026-08-26）。LLM判断で候補を絞ってから決定または棄権することで、人間判断との不一致リスクを制御する枠組み。
- XREPOTEST: Benchmarking Multilingual Repository-Level Unit Test Generation for Large Language Models — arXiv:2608.25939（2026-08-26）。リポジトリ制約下でのユニットテスト生成を多言語で評価し、文脈拡張と実際のテスト有効性のギャップを測る。
