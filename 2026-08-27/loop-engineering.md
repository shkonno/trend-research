## 今日の一言
AIエージェントの「ループ」は、単なる反復実行から、観測・帰属・監督・停止条件を設計する制御面そのものへ移りつつあります。

## トップ5

### 1. AI Agents Push Humans Out of the Loop
- 出典: arXiv position paper
- 日付: 2026-08-24
- リンク: https://arxiv.org/abs/2608.23642v1
- 要約: 自律化するAIエージェントに対して「human in the loop」を置くだけでは十分でなく、現行のエージェント設計は人間の有効な監督をむしろ難しくし、長期利用で監督者の認知スキルも劣化させうると論じています。HCIと自動化研究を接続し、監督者の判断力を維持する設計上のアフォーダンスと組織プロトコルを提案する点が、Loop engineeringの最重要論点です。
- なぜ面白いか:
  - 技術: ループ内に人間を置く設計を、単なる承認ボタンではなく、注意・判断・スキル維持を支えるインターフェースと運用プロトコルとして再定義しています。
  - 人文: ethicsの観点では、責任を人間に残す制度設計が、実際には責任能力を摩耗させる逆説を扱っています。historyの観点でも、航空・産業自動化で繰り返された「監督者の形骸化」がAIエージェントで再演されていることを示します。

### 2. ClawSentry: A Progressive Multi-Tier Security Monitor for Safeguarding Autonomous LLM Agents
- 出典: arXiv / GitHub
- 日付: 2026-08-21（GitHub更新確認: 2026-08-19）
- リンク: https://arxiv.org/abs/2608.21101v1 / https://github.com/Elroyper/ClawSentry
- 要約: LLMエージェントのリスクが、スキル導入、呼び出し時意図、実行時効果、実行後結果という制御ループ上の4地点で発生するとモデル化し、段階的なセキュリティ監督ゲートウェイを提案しています。Codex、Claude Code、Kimi CLI、Gemini CLIなどを横断するAgent Harness Protocolにより、エージェント内部を変更せずに統一ポリシーを適用する発想が実装面でも強いです。
- なぜ面白いか:
  - 技術: エージェントの各アクションを、事前審査・実行中判定・実行後証拠更新のループに分解し、曖昧なケースだけ高コストな意味解析へ送る設計が実用的です。
  - 人文: ethicsの観点では、安全性を「モデルの善意」ではなく、制度的なチェックポイントと監査可能な記録として扱っています。anthropologyの観点では、組織内の権限委譲や承認文化をソフトウェア・プロトコルへ翻訳する試みとして読めます。

### 3. PILOT Technical Report
- 出典: arXiv
- 日付: 2026-08-19
- リンク: https://arxiv.org/abs/2608.18637v2
- 要約: 推薦システム最適化のエージェントを、Experiment Manager、Search Plannerなどの役割に分け、安全・統計・権限境界を決定論的サービスが強制する「制約付き制御ループ」として設計しています。単なるメトリクス反応ではなく、実験計画・異常回復・ポストモーテムまでをループに含める点が、プロダクト実験のLoop engineeringとして参考になります。
- なぜ面白いか:
  - 技術: LLMが自由に本番を操作するのではなく、合法コマンドの封筒内で実験設計を提案し、統計的ガードレールを外部サービスが担う分担が明確です。
  - 人文: philosophyの観点では、知能を「自律的意思」ではなく、制約付き実験を積み重ねる探究プロセスとして捉えています。narrativeの観点では、実験の失敗や異常回復までを組織が学ぶ物語として保存する設計が興味深いです。

### 4. Graph Engineering
- 出典: GitHub repository
- 日付: 2026-08-13作成、2026-08-15更新（直近14日境界の古めだが関連性が高い）
- リンク: https://github.com/khanhtran0111/graph-engineering
- 要約: Agentic AIにおける状態、ルーティング、フィードバックループ、終了条件、回復、可観測性を「実行可能グラフ」の制御設計として整理する教材リポジトリです。READMEではGraph Engineeringを、知識グラフやグラフアルゴリズムではなく、確率的なLLM呼び出しを囲む明示的な実行制御として位置づけています。
- なぜ面白いか:
  - 技術: ノード、エッジ、ルーター、ポリシーを明示することで、暗黙のagent loopをテスト可能な制御面へ変換しています。
  - 人文: philosophyの観点では、エージェントの「意図」をブラックボックスに置かず、状態遷移と停止条件として外在化する設計思想が見えます。creativityの観点では、LLMの偶発性を消すのではなく、作品制作の編集台のように配置・反復・評価するための型を与えています。

### 5. TRACE: TRajectory Attribution for Automated Context Engineering
- 出典: arXiv
- 日付: 2026-08-10（14日より古いが、Loop engineeringへの関連性が高いため採用）
- リンク: https://arxiv.org/abs/2608.09153v1
- 要約: 本番AIエージェントの失敗ログやユーザーの訂正・言い換え・離脱シグナルから、プロンプト、知識ベース、ツール説明、手続き的スキルなどのコンテキスト層の欠陥を自動診断・修復するフィードバックループを提案しています。60件の不満足トレースで、根本原因帰属72.7%、修正有効性82%を報告しており、運用後のループ改善に焦点を当てています。
- なぜ面白いか:
  - 技術: エージェント実行軌跡をデバッグ資源として扱い、モデル再学習ではなくコンテキスト更新で素早く失敗を閉じる運用ループを示しています。
  - 人文: anthropologyの観点では、ユーザーの訂正や離脱という微細な行動を、システム改善の「現場民族誌」のように読む発想があります。ethicsの観点では、明示的フィードバックを強制せず暗黙シグナルを使うため、プライバシー・同意・監査の境界設計が重要になります。
