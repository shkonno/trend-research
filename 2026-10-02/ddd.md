## 今日の一言

AI/LLM時代のDDDは「モデルをどう作るか」だけでなく、「人間とAIが同じ文脈・言葉・判断履歴をどう共有するか」という組織設計のテーマに広がっている。

## トップ5

### 1. ゴミの分別とポカヨケから学んだDDD・TDD 〜ブラジル人エンジニアが日本の生活で気づいたこと〜
- 出典: Qiita
- 日付: 2026-10-01
- リンク: https://qiita.com/thiagovpaz/items/ec4fdcec5a302afd11bb
- 要約: 日本のゴミ分別、ポカヨケ、電車の定時運行などの生活経験を、DDDのレイヤー分離、Value Object、TDDのリズムに重ねて説明する記事。技術概念を抽象的な設計原則ではなく、日常の秩序やミス防止の仕組みとして捉え直している。
- なぜ面白いか:
  - 技術: Value Objectを「不正な値をそもそも作れないポカヨケ」として説明しており、DDDの型設計をチーム内で伝える教材として使いやすい。
  - 人文: DDDが文化翻訳の道具になっている点が面白い。ソフトウェア設計の語彙が、生活習慣・都市の清潔さ・集団的な規範の理解と接続されている。

### 2. Hexagen-Monaco: Governance Engine for Human and Agentic Systems
- 出典: GitHub リポジトリ
- 日付: 2026-10-02 更新（作成: 2026-03-01）
- リンク: https://github.com/martinkrakowski/hexagen-monaco
- 要約: TypeScriptモノレポ向けのガバナンスエンジンで、DDDとヘキサゴナルアーキテクチャをYAMLマニフェストとして表現し、結合や境界違反をビルド時に検出する。READMEでは「Architecture should compile」「Human and Agentic Systems」を掲げ、LLMアダプタ等のテンプレートも含む。
- なぜ面白いか:
  - 技術: 境界づけられたコンテキストや依存方向をドキュメントではなくコンパイル可能な制約にすることで、AIエージェントによるコード変更にもアーキテクチャガードレールを掛けられる。
  - 人文: これは「設計判断を人間の記憶に置かない」方向の実験でもある。AIが開発に混ざるほど、組織文化としての暗黙知を機械可読な規範に変換する必要が高まる。

### 3. ai-ddd-devtrack
- 出典: GitHub リポジトリ
- 日付: 2026-10-02 更新（作成: 2026-09-05）
- リンク: https://github.com/watanabe-1/ai-ddd-devtrack
- 要約: 技術学習の目標、学習記録、資格試験の進捗を管理するための、AI coding agent と DDD のサンプルプロジェクト。PlantUMLを設計のSource of Truthとし、Spring Bootバックエンド、Reactフロントエンド、Flyway、JPA adapter、domain unit test、ArchUnitによるlayer dependency確認などを備える。
- なぜ面白いか:
  - 技術: AI coding agentに実装を任せる前提で、PlantUML・テスト・ArchUnitを設計の足場として置いているため、DDDを「AIに伝える仕様体系」として扱っている。
  - 人文: ユビキタス言語は会議室だけでなく、エージェントに渡すプロンプトや図にも宿る。人間チームとAIの間で、何をSource of Truthとみなすかという合意形成の問題が見える。

### 4. 【勉強会】「AI時代『考える力』をどう鍛える？具体抽象トレーニング」に参加して考えたこと
- 出典: Qiita
- 日付: 2026-09-29
- リンク: https://qiita.com/ko1_tktn/items/5f0a18a0c91b398dc7d6
- 要約: AIの進化が速い時代に、エンジニアが具体と抽象を行き来し、ユーザーの問題を捉える力をどう鍛えるかを扱った勉強会参加記。ドメインモデリング、ユビキタス言語、コアドメインへの気づき、質問によるバイアスの問題が言及されている。
- なぜ面白いか:
  - 技術: DDDのモデリングは、抽象化の演習であり、単なるクラス設計ではなく「どの問いを立てるか」の技術として再提示されている。
  - 人文: AIが答えを速く生成するほど、人間側には問いの立て方、思い込みの自覚、相手の文脈を読む力が残る。DDDのワークショップ性が、AI時代の職能教育と結びついている。

### 5. Automating Domain-Driven Design: Experience with a Prompting Framework
- 出典: arXiv
- 日付: 2026-03-27（古いが関連性が高いため採用）
- リンク: https://arxiv.org/abs/2603.26244
- 要約: LLMを使ってドメイン駆動設計を自動化するプロンプティングフレームワークに関する論文。直近14日ではないが、イベントストーミング、ユビキタス言語、LLMによるモデリング支援という今回の調査軸に最も直接つながる学術的候補として確認された。
- なぜ面白いか:

  - 人文: DDDを自動化する試みは、「ドメイン専門家との対話」をどこまで機械に委ねられるかという境界問題を露出させる。便利さの一方で、言葉の意味や組織内の権力関係までモデル化できるのかが問われる。
