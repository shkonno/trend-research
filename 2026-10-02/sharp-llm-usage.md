### 1. Grist: confidence-gated coding-agent harness
- 出典: Web / Hacker News / 公式サイト
- 日付: 2026-10-01（HN掲載）
- リンク: https://grist.lol/
- 要約: Gristは、コーディングタスクを「最安で十分なモデル段」にルーティングし、検証済みの変更だけを記憶するという発想のエージェント・ハーネス。サイト上では、confidence-gated model routing、institutional memory、BYOK、作業ツリー上での編集、承認・テストに基づく記憶を前面に出している。
- なぜ面白いか:
  - 技術: LLM利用を「単一モデルへの依頼」ではなく、信頼度ゲート、モデル選択、テスト結果、記憶の更新を含む実行基盤として扱っている。
  - 人文: 人間の熟練者が持つ「この変更は覚える価値がある」という判断を、組織の記憶として制度化しようとしている点が面白い。AIとの協働が、個人の会話術からチームの作法へ移っている。

### 2. OpenWand: 作業中の文脈を自動で拾うLLMデスクトップ共働インターフェース
- 出典: Web / GitHub / Hacker News
- 日付: 2026-09-19（HN掲載）、GitHub更新 2026-09-30
- リンク: https://github.com/SunnyLich/OpenWand
- 要約: OpenWandは、ウィンドウ切替やコピー&ペーストを減らし、ユーザーが作業している場所の文脈を自動または手動で取り込んでLLMに渡すデスクトップ向けインターフェース。ローカルファースト、クロスプラットフォーム、BYOモデル、音声入出力、Python-firstの拡張性を掲げている。
- なぜ面白いか:
  - 技術: プロンプトを頑張って書くのではなく、意図選択と文脈収集をUI側で支援することで、LLMの入力品質を日常作業の流れに埋め込んでいる。
  - 人文: 「AIに相談するために仕事を中断する」負担を減らす設計で、LLMが別室の助言者から机上の相棒へ近づく。注意の断片化をどう防ぐかという、働き方の問題にも踏み込んでいる。

### 3. Claude Code動的ワークフローのトークン消費を約80%削減した実例（古いが重要）
- 出典: Hacker News投稿
- 日付: 2026-09-06（直近14日より古いが、実践例として重要）
- リンク: https://news.ycombinator.com/item?id=49587379
- 要約: 投稿者は、Claude Codeで動的ワークフローを毎回LLMに通す代わりに、過去数週間の `~/.claude/projects` にある実行履歴をClaudeに分析させ、共通パターンを抽出してワークフローを合成するツールを作らせた。結果として、実行・監視のトークン消費が従来の約20%まで下がり、5〜6時間かかっていた処理が20〜40分程度になったと報告している。
- なぜ面白いか:
  - 技術: LLMを毎ステップの推論エンジンとして酷使するのではなく、反復パターンを発見してツール化し、以後はLLM呼び出しを減らすという「LLMでLLM依存を減らす」使い方になっている。
  - 人文: 熟練者が作業の型を見抜いて手順書や治具を作るのに近く、AI利用の成熟が「もっと賢いモデル」ではなく「モデルを呼ばない勇気」に現れている。失敗例やコスト増を観察し、作業そのものを再設計する姿勢が鋭い。

### 4. Shopify: GistingでLLMエージェントのシステムプロンプトを圧縮（古いが重要）
- 出典: Web / Shopify Engineering
- 日付: 2026-08-21（直近14日より古いが、実運用の文脈圧縮例として重要）
- リンク: https://shopify.engineering/gisting
- 要約: ShopifyはSidekick GraphQL agentの約6,000トークンのシステムプロンプトを、知識蒸留で学習した約1,500のgist tokenへ4:1圧縮したと説明している。品質を保ちながら、TTFTを438msから354ms、エンドツーエンド遅延を6.8秒から4.2秒へ下げ、QPSも20.2から23.4へ上げたと報告している。
- なぜ面白いか:
  - 技術: 長いシステムプロンプトの「ふるまい」を特殊トークン埋め込みへ蒸留し、推論時の文脈長・レイテンシ・GPU使用量を直接削る実運用テクニックになっている。
  - 人文: これはプロンプトを文章として磨く文化から、プロンプトをインフラ資源として扱う文化への転換を示す。言葉で命令するだけでなく、言葉のコストを測り、組織のサービス品質へ翻訳している点が興味深い。

### 5. Breaking Babel / SMART: 字幕翻訳で自己進化するマルチエージェントを使うarXiv論文
- 出典: arXiv
- 日付: 2026-09-29
- リンク: https://arxiv.org/abs/2609.38660
- 要約: SMARTは、長尺字幕翻訳向けに、シリーズ単位の永続メモリ、動的ルーター、Mixture-of-Agents、用語検証、字幕制約検証、文脈検索、judge-refiner loopを組み合わせる。テスト時にプロンプトとルーティング方針を更新し、Subtitle Arenaの15方向で比較対象より良いMQMスコアを出したと報告している。
- なぜ面白いか:
  - 技術: コンテキスト検索、制約検証、批評によるプロンプト更新、ルーティング更新を、翻訳という評価しやすい領域で一つの閉ループにしている。
  - 人文: 字幕翻訳は単語変換ではなく、作品の記憶、ジャンル、時代、文化的ニュアンスを扱う作業であり、LLMワークフローが「意味の連続性」をどう維持するかを試す格好の題材になっている。AIが文化的媒介者になるとき、検証軸も単なる正誤からスタイルと文脈へ広がる。
