### 1. Building verification loops in Claude Code with skills
- 出典: Claude公式ブログ
- 日付: 2026-07-22（直近14日より少し古いが、検証ループ実践として重要）
- リンク: https://claude.com/blog/building-verification-loops-in-claude-code-with-skills
- 要約: Anthropicは、Claude Codeの作業を「コンテキスト収集 → 実行 → 検証 → 必要なら再実行」というループとして捉え、型チェック、lint、テスト、実行時エラー、手動確認手順をスキル化して検証可能にする方法を説明している。単発の依頼ではなく、普段人間が暗黙に行っている確認作業を、エージェントが反復できる手順として明文化するのが核になっている。
- なぜ面白いか:
  - 技術: LLM活用の品質を、プロンプト文面ではなく決定的シグナルと再試行手順に接続する「検証可能なハーネス設計」として扱っている。
  - 人文: 人間の熟練はしばしば「最後に何を見るか」という身体化された確認に宿るが、それをスキルとして外部化する動きは、職人芸を手順へ翻訳する文化的変化でもある。AIに任せるほど、人間が何を信頼の根拠にしていたかが見える。

### 2. Skill-Use: Can LLMs Actually Use Skills in Agentic Harnesses?
- 出典: arXiv
- 日付: 2026-08-05
- リンク: http://arxiv.org/abs/2608.04828
- 要約: LLMエージェントが、名前と短い説明だけを見て適切なスキルを呼び出し、手順を守り、禁止操作を避けられるかを評価するベンチマーク。79の実スキルと177の実行可能タスクで、Trigger、Compliance、Boundaryを分けて測り、信頼できるスキル利用はまだ難しいと報告している。
- なぜ面白いか:
  - 技術: 「スキルを書けば使ってくれる」という前提を分解し、発火・遵守・境界管理を別々に測ることで、エージェント運用の失敗箇所を診断可能にしている。
  - 人文: これは新人にマニュアルを渡すだけでは仕事にならない、という組織学習の問題に近い。手順書の存在と、状況に応じて手順を選び守る能力は別物だと示している点が鋭い。

### 3. Diagnosing Tool-Selection Reasoning in LLM Agents with Canary Tools
- 出典: arXiv
- 日付: 2026-08-05
- リンク: http://arxiv.org/abs/2608.04719
- 要約: MCPツールセットに診断用の「カナリアツール」を混ぜ、エージェントがなぜ誤ったツールを選ぶのかを、意味的デコイ、パラメータ罠、能力ミラージュ、前提条件の見落とし、時間的デコイ、粒度トラップの6類型で分析する研究。単に成功率を見るのではなく、ツール選択推論の癖をプロファイル化する。
- なぜ面白いか:
  - 技術: MCP時代の評価を「正解/不正解」から、ツール選択の脆弱性タイプを特定するデバッグ手法へ進めている。
  - 人文: 人間の職場でも、道具の選択ミスは知識不足だけでなく、権限、タイミング、粒度、前提確認の失敗から起きる。エージェントのミス分類は、人間組織の事故分析に似た言葉をAI運用へ持ち込んでいる。

### 4. dn / Denoise: meld, loop, land
- 出典: GitHubリポジトリ（Hacker News掲載で確認）
- 日付: 2026-07-28（HN掲載日）
- リンク: https://github.com/chesapeakedev/dn
- 要約: `dn`は、Issueやローカル仕様をリポジトリ内の永続的なMarkdown計画に変換し、OpenCode、Cursor、Claude Code、Codex CLIなどへ渡して、実装、レビュー、PR修正までを進めるCLI。チャット窓に閉じた一回限りの文脈ではなく、計画と受け入れ条件をリポジトリに残すことで、エージェント間・セッション間の引き継ぎを可能にする。
- なぜ面白いか:
  - 技術: コンテキストを会話履歴ではなくバージョン管理された計画ファイルに置くことで、LLMの作業をレビュー可能・再開可能なSDLC成果物へ変換している。
  - 人文: 「速くコードを書く」だけではソフトウェアは完成しない、という問題意識が明確だ。AI導入で失われがちな責任の所在を、計画、承認、受け入れ条件という共同作業の形式に戻している。

### 5. Armature: Analytics and evals for your MCP
- 出典: Armature公式サイト（Hacker News掲載で確認）
- 日付: 2026-08-03（HN掲載日）
- リンク: https://armature.tech/
- 要約: MCPサーバー、Claude Connector、ChatGPT Appなどで実際のユーザーセッションを再構成し、ユーザー意図、エージェントの思考、ツール呼び出し、失敗ループ、成功率を分析するサービス。さらに、実利用から上位ユースケースや失敗パターンを抽出し、それをMCP/CLI向けの評価シナリオに変換する点が実践的。
- なぜ面白いか:
  - 技術: 本番の失敗ログをそのままevalへ戻す閉ループを作り、LLMアプリの改善を「観測 → 根因分類 → 回帰テスト」に接続している。
  - 人文: ユーザーはAIクライアントの中で行動し、提供者のUIには現れないため、従来のプロダクト分析では生活実態が見えにくい。LLM時代のプロダクト理解は、クリックではなく意図と挫折の解釈に寄っていく。
