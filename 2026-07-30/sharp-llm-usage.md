## トップ5

### 1. AI導入は“利用量”ではなく、検証・レビュー・複数エージェント管理まで進む段階設計で見る
- 出典: X投稿（Boris Cherny / @bcherny）
- 日付: 2026-07-17
- リンク: https://x.com/bcherny/status/2077929379661844559
- 要約: Boris Chernyは、個人エンジニアはClaudeで10倍の生産性を出し始めている一方、組織では導入段階の差が大きいとし、AI導入を4段階で捉える視点を提示している。上位段階では、Claudeに作業の自己検証、Auto Mode、自動コードレビュー、セキュリティレビュー、複数エージェント管理、`/loop`・`/batch`・worktree分離などを組み合わせる。
- なぜ面白いか:
  - 技術: LLM活用の成熟度を「チャットが便利」ではなく、検証・レビュー・権限・並列実行・失敗時の再設計まで含む運用アーキテクチャとして測っている。
  - 人文: これはAIを“賢い個人助手”として見る段階から、“組織の労働分業を再設計する制度”として見る段階への転換である。人間の価値も、出力作業そのものより、ボトルネックの発見・ガードレール設計・成果の判断へ移っていく。

### 2. Prompt injection対策は、モデル性能だけでなくAuto Modeやプローブを重ねる防御として設計する
- 出典: X投稿（Boris Cherny / @bcherny）
- 日付: 2026-07-24
- リンク: https://x.com/bcherny/status/2080713091688583312
- 要約: Boris ChernyはOpus 5について、単なるコーディング性能だけでなくAnthropicで最もprompt-injectionされにくいモデルだと紹介し、モデルのアラインメント、prompt injectionプローブ、Claude CodeのAuto Modeを重ねることで攻撃成功率を大きく下げられると述べている。LLMを外部情報やツールに接続するほど、プロンプトは文章術ではなく防御面の一部になる。
- なぜ面白いか:
  - 技術: コンテキスト注入やツール実行を伴うワークフローでは、モデル・プローブ・実行モードを層状に組み合わせたセキュリティ設計が必要になる。
  - 人文: “AIに任せる”とは、信頼の委任であると同時に、悪意あるテキストに権限を奪われないための制度設計でもある。便利さを最大化するほど、誰の言葉を信じるのかという権威の問題が前景化する。

### 3. Context engineering intro: CLAUDE.md、INITIAL.md、PRP、検証ループで“vibe coding”を再現可能にする
- 出典: GitHub / Xでの紹介（Context Engineering Intro）
- 日付: 2026-07下旬にXで再拡散を確認（リポジトリ自体の初出日は未確認）
- リンク: https://github.com/coleam00/context-engineering-intro
- 要約: “Context engineering is the new vibe coding”を掲げるテンプレートで、`CLAUDE.md`にプロジェクト規約、`INITIAL.md`に機能要件、PRP（Product Requirements Prompt）に実装計画と検証手順をまとめ、Claude CodeなどのAIコーディング支援を文脈・計画・テストで縛る。X検索では、Claude Code向けの実践テンプレートとして、オンデマンドの文脈読み込みやvalidation loopと併せて言及されていた。
- なぜ面白いか:
  - 技術: 成功条件、既存規約、参照ファイル、テストコマンドを明文化し、LLMの一回きりの出力を検証可能な実装サイクルへ変換している。
  - 人文: “ノリで作る”vibe codingを否定せず、むしろ創造性を保ったまま失敗を回収できる足場を作っている点が重要である。自由な発想と組織的な再現性の折り合いをつける、小さな方法論になっている。

### 4. COVENANT: 自然言語ワークフローをコンパイルして、エージェントの手順逸脱を防ぐ
- 出典: arXiv
- 日付: 2026-07-28
- リンク: http://arxiv.org/abs/2607.25400v1
- 要約: LLMエージェントに自然言語で業務手順を与えるだけでは、対話が長くなるにつれて必須ステップを飛ばす、許可されていない分岐を選ぶ、正しいステップを誤った引数で実行するなどの“workflow misalignment”が起きる。COVENANTは自然言語ワークフローをコンパイラとインタプリタの形に落とし、エージェント実行を手順に沿わせるアーキテクチャを提案している。
- なぜ面白いか:
  - 技術: プロンプト内の手順をモデルの記憶と善意に任せず、実行可能な制御構造として外部化する点が、実務エージェントの信頼性向上に直結する。
  - 人文: 仕事の手順とは、単なる効率化のためのチェックリストではなく、責任の所在や例外処理の文化を含む社会的な約束である。自然言語をコンパイルする発想は、人間の暗黙ルールをどこまで機械に移せるのかという問いを突きつける。

### 5. The Illusion of Secure LLM Code: “安全に書いて”だけでは足りず、反復リプロンプトと実テストが必要
- 出典: arXiv
- 日付: 2026-07-26
- リンク: http://arxiv.org/abs/2607.23710v1
- 要約: AIコーディング支援が生成した認証コードを、静的解析と動的ペネトレーションテストで評価し、Basic、Secure、NIST-Based、Repromptingという複数のプロンプト戦略を比較する研究。機能的または一般的に“安全”と指示しただけのコードにはセキュリティギャップが残り、反復的なリプロンプトや具体基準に基づく検証が重要になることを示している。
- なぜ面白いか:
  - 技術: セキュリティ品質をプロンプト文言だけで保証せず、標準、静的解析、動的攻撃テスト、再プロンプトを組み合わせる評価ループとして扱っている。
  - 人文: “AIが安全なコードを書いた”という安心感は、人間が検査責任を手放す物語にもなりうる。失敗を前提に検証する態度は、AI時代の専門職倫理そのものに近い。
