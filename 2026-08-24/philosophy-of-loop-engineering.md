## 今日の一言
Loop Engineering は新語としての単発ニュースよりも、「評価・反省・人間介入・自己改変」をどう閉じた実践知の循環にするかという、AIエージェント時代のサイバネティクス的設計思想として濃く読める日でした。

## トップ5

### 1. Darwin Gödel Machine: Open-Ended Evolution of Self-Improving Agents
- 出典: arXiv
- 日付: 2025-05-29 投稿、2026-03-12 改訂（直近14日外だが重要）
- リンク: https://arxiv.org/abs/2505.22954
- 要約: DGM は、エージェントが自分自身のコードを反復的に変更し、コーディングベンチマークで各変更を経験的に検証しながら、改善候補のアーカイブを維持する自己改善システムです。理論上のゲーデル・マシンを「証明」ではなく「実験・評価・保存」のループに置き換えている点が、実務的な Loop Engineering に非常に近いです。
- なぜ面白いか:
  - 技術: 自己改変、ベンチマーク評価、候補アーカイブをつなぐことで、LLM エージェント改善を閉じた反復システムとして扱っています。
  - 人文: 「正しさを証明してから進む」近代理性ではなく、「暫定的に試し、失敗を記録し、次の行為に反映する」プラグマティズム的な知のモデルへ重心が移っています。サイバネティクスのフィードバック制御を、ソフトウェア開発者自身の認識論として読み替えられます。

### 2. The AI Scientist-v2: Workshop-Level Automated Scientific Discovery via Agentic Tree Search
- 出典: arXiv
- 日付: 2025-04-10 投稿（直近14日外だが重要）
- リンク: https://arxiv.org/abs/2504.08066
- 要約: AI Scientist-v2 は、仮説生成、実験設計、実行、分析、可視化、論文執筆までをエージェント的ツリー探索で回す研究自動化システムです。図表の品質改善に VLM フィードバックループを組み込み、研究活動そのものを多段の検証ループとして実装しています。
- なぜ面白いか:
  - 技術: 実験マネージャー、ツリー探索、レビュー/視覚フィードバックを組み合わせ、研究ワークフローを反復可能なエージェント制御問題に変換しています。
  - 人文: 科学を「天才のひらめき」ではなく、仮説と検証が制度的に折り返される手続きとして捉える点で、ポパー的反証主義や実験室人類学と接続します。Loop Engineering はここで、科学的実践知をソフトウェア化する思想になります。

### 3. Building effective agents
- 出典: Anthropic Engineering ブログ
- 日付: 2024-12-19（直近14日外だが基礎資料として重要）
- リンク: https://www.anthropic.com/engineering/building-effective-agents
- 要約: Anthropic は、複雑なフレームワークより単純で組み合わせ可能なパターンを推奨し、その一つとして「Evaluator-optimizer」を示しています。これは一つの LLM 呼び出しが生成し、別の LLM 呼び出しが評価とフィードバックを与えるループです。
- なぜ面白いか:
  - 技術: 生成器と評価器を分離することで、品質改善をプロンプト一発勝負ではなく観測可能な制御ループとして設計できます。
  - 人文: 判断者をシステム内に置く設計は、行為者が自分の行為を省察する「反省」の構造を工学化したものです。人間の熟練も、行為・観察・修正の反復で育つという実践知の見方と重なります。

### 4. 12-Factor Agents - Principles for building reliable LLM applications
- 出典: HumanLayer / GitHub
- 日付: 2025-03-30 作成、GitHub メタデータ上は 2026-08-24 時点でも更新あり（内容の初出は直近14日外）
- リンク: https://github.com/humanlayer/12-factor-agents
- 要約: 12-Factor Agents は、本番投入できる LLM アプリケーションの原則集で、良いエージェントは「プロンプトとツール袋でゴールまでループ」するものではなく、ほとんどが通常のソフトウェアで構成されると論じています。文脈窓の所有、人間へのツール呼び出し、制御フローの所有など、ループを暴走させず運用可能にする設計原則が中心です。
- なぜ面白いか:
  - 技術: コンテキスト、実行状態、停止/再開、人間承認を明示的に設計することで、LLM の反復処理を監査可能なワークフローに変えます。
  - 人文: ここでのループは自律性の礼賛ではなく、責任の所在を残すための制度設計です。職人の勘を排除するのではなく、どこで人間が判断を差し戻すかを形式化する「実践知の足場」として読めます。

### 5. Reflexion: Language Agents with Verbal Reinforcement Learning
- 出典: arXiv
- 日付: 2023-03-20 投稿、2023-10-10 改訂（古いが Loop Engineering の思想史として重要）
- リンク: https://arxiv.org/abs/2303.11366
- 要約: Reflexion は、言語エージェントがタスクのフィードバックを自然言語で反省し、その反省をエピソード記憶に保存して次試行の意思決定を改善する枠組みです。重み更新ではなく言語的フィードバックで学習を近似するため、開発者が観察しやすい反復改善ループになります。
- なぜ面白いか:
  - 技術: 外部または内部のフィードバック信号を言語化し、記憶バッファを介して次の行動を変えるため、デバッグ可能な学習ループを作れます。
  - 人文: 反省文を残すエージェントは、単なる自動化機械ではなく「失敗の物語」を蓄積する存在として設計されています。これは、知識を命題ではなく経験の再記述として扱う認識論に近いです。
